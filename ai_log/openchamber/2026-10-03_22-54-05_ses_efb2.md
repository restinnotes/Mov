## What the document says

- **Host** becomes operational owner of its courses: course-scoped roster read/upload/import/patch, course-bound game + question CRUD + reorder + JSON import/export, own/co-hosted session listing + HTML report + raw/Canvas CSV download, guest reconciliation, course-first room creation.

### P0 — Authorization model is self-contradictory

2. **List-games union leaks course existence.** "HOST on C (union legacy grants)" — if game G is in course C the caller has no HOST on but holds a legacy grant, under which course does it appear? Does listing it leak C's existence/name to a non-member? No rule.
